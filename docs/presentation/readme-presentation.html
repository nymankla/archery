.NET 10 · Aspire distributed application

Archery Club
Management

Members, membership fees, competitions, results, training attendance, and the guests who compete without joining. A secured minimal-API backend and an interactive Blazor Server frontend, orchestrated with Redis, PostgreSQL, and Keycloak.

.NET 10 Aspire 13.4 Blazor Server PostgreSQL Redis Keycloak

01 — Architecture

Four runtime pieces,
one shared library

Redis, PostgreSQL, and Keycloak stand behind the API; the API stands behind the web frontend. Every service starts only once its dependencies report healthy, and every call between them goes through Aspire service discovery.

aspire.AppHost

Orchestrator

Defines the resource graph. No business logic.

aspire.ApiService

Minimal-API backend

Domain logic, EF Core, spreadsheet import/export. Keycloak JWT bearer.

aspire.Web

Blazor interactive server

Keycloak OIDC login, calls the API, caches output in Redis.

aspire.ServiceDefaults

Shared library

OpenTelemetry, service discovery, resilience, /health + /alive.

Tests

xUnit integration

Boots the full AppHost in-process, incl. Postgres checks.

UnitTests

xUnit unit

Fast service tests. No containers required.

02 — Domain model

Eight entities,
five enums

Persisted with EF Core through ArcheryDbContext; migrations apply automatically at API startup.

Member

Contact details, personnummer (unique), date of birth, join date, active flag, preferred bow class.

MembershipFee

A member's fee for a year — amount, due date, status. Unique per member + year.

Competition

Date, location, round type, and type — Indoor / Outdoor / ThreeD / Field.

CompetitionResult

Tied to a member or an external participant, enforced by a DB check constraint.

CompetitionParticipant

Registration of a member or guest into a competition.

TrainingSession

A training date with optional notes.

TrainingAttendance

Member or guest at a session — same either/or check constraint, unique per session + participant.

ExternalParticipant

A guest competitor from another club — not a member.

BowClass · Recurve / Compound / Barebow / Traditional AgeClass · Cadet / Junior / Senior / Master Gender FeeStatus CompetitionType
Deleting a member or external participant cascades to their competition results, registrations, and training attendance — those rows can't outlive the participant.

05 — Import, export & bulk operations

Spreadsheets in and out,
conflicts out as 409

Spreadsheet import
Members, competitions, and external participants from CSV or .xlsx — parsed by SpreadsheetParser using CsvHelper and ClosedXML.
Spreadsheet export
Training attendance as CSV or .xlsx via SpreadsheetWriter — the generic counterpart to the parser.
Bulk fee creation
POST /membership-fees/bulk generates fees for many members at once, optionally filtered by age.
Conflict handling
Domain conflicts — a duplicate fee for a member/year, a duplicate personnummer — surface as HTTP 409/400, not a 500.

06 — Web frontend

Interactive server,
authenticated through Keycloak

Dashboard Members Competitions Fees overview Training attendance Training history External participants

OIDC code flow

Cookie + OIDC, tokens refreshed via TokenRefreshService

Small cookies

MemoryCacheTicketStore keeps the session ticket small

Survives restarts

Data-protection keys persisted to disk

Bearer attached

ArcheryApiClient via BearerTokenHandler

Configurable

Idle-timeout & refresh via AuthSession

Both services default to the sv-SE culture — override with the Locale config key. File downloads go through FileDownloader, a reusable JS-interop Blob helper — Blazor Server has no direct client filesystem access.

07 — Getting started

One command
boots everything

.NET 10 SDK Docker Desktop or Podman Aspire CLI · optional
run
# AppHost boots Redis, PostgreSQL, Keycloak, the API, and the Web frontend
dotnet run --project aspire.AppHost

Dashboard URL prints in the terminal — typically https://localhost:17034. Migrations and the Keycloak realm import happen automatically on first run.

08 — Deploy & test

Publish, deploy, verify

publish & deploy
# Docker Compose deployment already configured in AppHost.cs
aspire publish -o aspire-output/docker
aspire deploy
build & test
dotnet build Archery.sln
dotnet test Archery.sln      # unit + integration
dotnet test UnitTests        # fast, no containers
Integration tests in Tests boot the full AppHost in-process and need a running container runtime.
